## 当前理解

### 网络与互联网

- **网络**：由若干节点和连接这些节点的链路组成。节点可以是主机、集线器、交换机或路由器。
- **互联网**：多个网络通过路由器互相连接形成的更大网络，可以理解为“网络的网络”。
- **主机**：与网络直接相连、由用户使用的计算机或设备。

从工作方式看，互联网可以分成两部分：

| 部分 | 作用 | 示例 |
|---|---|---|
| 边缘部分 | 用户直接使用，负责通信和资源共享 | PC、手机、服务器、游戏客户端 |
| 核心部分 | 为边缘部分提供连通性和交换 | 路由器、网络链路、骨干网络 |

### 交换方式

| 方式 | 基本过程 | 特点 | 面试表达 |
|---|---|---|---|
| 电路交换 | 建立连接 -> 数据传输 -> 释放连接 | 通信期间独占资源，资源利用率低 | 类似传统电话，一条链路被占住 |
| 报文交换 | 整个报文作为单位存储转发 | 不独占完整通路，但单个报文可能很大 | 比电路交换灵活，但转发粒度较粗 |
| 分组交换 | 报文拆成多个分组，逐跳存储转发 | 网络资源利用率更高，是现代互联网基础 | 类似把大包裹拆成多个小包裹分别中转 |

分组交换不是“所有分组一定并行走不同路径”，而是每个分组可以独立转发，路由器按当前路由表决定下一跳。

## 性能指标

| 指标 | 含义 | 常见单位 / 公式 | 易混点 |
|---|---|---|---|
| 速率 | 数据传输速率，也叫数据率或比特率 | bit/s、bps | 描述实际或标称传送快慢 |
| 带宽 | 通信线路理论上能通过的最高数据率 | bit/s、bps | 更偏“能力上限” |
| 吞吐量 | 单位时间内实际通过的数据量 | bit/s、B/s 等 | 受拥塞、协议开销、设备性能影响 |
| 发送时延 | 把数据帧推到链路上所需时间 | 数据长度(bit) / 发送速率(bit/s) | 和链路长度无关 |
| 传播时延 | 信号在链路上传播所需时间 | 信道长度(m) / 信号传播速率(m/s) | 和数据大小无关 |
| 时延带宽积 | 链路中“正在路上”的数据量 | 传播时延 x 带宽 | 可理解为管道容量 |
| RTT | 发送端发出分组到收到确认的往返时间 | Round-Trip Time | 常用于估计重传、延迟体验 |

面试中可以这样区分：带宽像水管理论直径，吞吐量像实际流过的水量；时延关注多久到，吞吐量关注单位时间能过多少。

## 网络体系结构

协议、接口和服务是分层模型的三个基本概念：

- **协议**：同层实体之间通信的规则，包含语法、语义和同步。
- **接口**：相邻两层之间交换信息的连接点。
- **服务**：下层向上层提供的能力。

常见模型对比：

| 模型 | 层次 |
|---|---|
| OSI 七层 | 物理层、数据链路层、网络层、运输层、会话层、表示层、应用层 |
| TCP/IP 四层 | 网络接口层、网际层、运输层、应用层 |
| 教学五层 | 物理层、数据链路层、网络层、运输层、应用层 |

## 五层模型：一条消息如何发送

以“给异地朋友发一条消息”为例：

| 层级 | 主要职责 | 典型信息 |
|---|---|---|
| 应用层 | 组织应用语义，例如文本、图片、收发人 | HTTP、SMTP、应用自定义协议，数据单位常称报文 |
| 运输层 | 负责进程到进程通信 | TCP 报文段、UDP 用户数据报、端口号 |
| 网络层 | 负责跨网络寻址和路由 | IP 数据报、源 IP、目的 IP |
| 数据链路层 | 负责相邻节点之间传输 | 帧、源 MAC、目的 MAC、差错检测 |
| 物理层 | 把比特变成电信号、光信号或无线电波 | 比特、电压、频率、接口、传输介质 |

发送端逐层加头封装，接收端逐层去头解封装。中间路由器通常只需要处理到网络层：它看 IP 地址决定下一跳，再重新封装下一跳所需的链路层帧。

## IP 与 MAC 的区别

| 项目 | IP 地址 | MAC 地址 |
|---|---|---|
| 作用 | 跨网络逻辑寻址 | 局域网或一段链路内的物理寻址 |
| 变化范围 | 从源到目的的逻辑目标相对稳定 | 每一跳的源 / 目的 MAC 都会变化 |
| 类比 | 最终收件地址 | 当前这一段投递单 |

一句话：IP 决定“最终去哪”，MAC 决定“这一跳交给谁”。

- 发送时延和传播时延分别受什么因素影响？
- 为什么 IP 地址全程相对稳定，而 MAC 地址逐跳变化？
