## DNS：域名到 IP 的映射

DNS 的作用是把人更容易记忆的域名转换为机器通信需要的 IP 地址：

```text
www.example.com -> DNS 查询 -> 目标服务器 IP
```

域名是层次结构，越靠右层级越高。例如：

```text
mail.cctv.com
三级域名.二级域名.顶级域名
```

域名不区分大小写。常见顶级域名包括：

| 类型 | 示例 | 含义 |
|---|---|---|
| 国家 / 地区顶级域名 | `.cn`、`.us`、`.uk` | 对应国家或地区 |
| 通用顶级域名 | `.com`、`.org`、`.edu`、`.gov` | 公司、组织、教育、政府等用途 |

DNS 常见使用 UDP 53 端口。后续需要补充递归查询、迭代查询、本地 DNS 缓存和 TCP 53 的使用场景，本页暂不展开。

## FTP：控制连接与数据连接

FTP 使用客户 / 服务器模式，并基于 TCP 工作。经典 FTP 会区分两条连接：

| 连接 | 常见端口 | 作用 |
|---|---:|---|
| 控制连接 | TCP 21 | 传输登录、命令、响应等控制信息 |
| 数据连接 | TCP 20 | 传输文件数据 |

面试记忆重点不是死背“两个端口”，而是理解：控制信息和文件数据被拆到不同连接中。后续如果继续学习，还要区分主动模式、被动模式和防火墙 / NAT 对 FTP 的影响。

## WWW：URL、HTTP、HTML

万维网访问可以拆成三个概念：

| 概念 | 作用 | 例子 |
|---|---|---|
| URL | 描述资源在哪里，以及用什么协议访问 | `https://example.com:443/path` |
| HTTP | 客户端和服务器传输超文本资源的应用层协议 | 请求 / 响应、状态码、Header、Body |
| HTML | 页面内容的标记语言 | 文本、链接、结构和资源引用 |

URL 基本格式：

```text
<协议>://<主机>:<端口>/<路径>
```

HTTP 默认端口是 TCP 80；HTTPS 默认端口是 TCP 443。当前笔记只覆盖 HTTP 基础入口，后续还需要补 HTTPS 加密大意、状态码、请求方法和抓包示例。

## 常见应用层协议速查

| 协议 / 应用 | 常见传输层协议 | 常见端口 | 当前记忆点 |
|---|---|---:|---|
| DNS | UDP | 53 | 域名解析到 IP；后续补 TCP 场景 |
| FTP 数据连接 | TCP | 20 | 文件数据传输 |
| FTP 控制连接 | TCP | 21 | 命令和响应控制 |
| TELNET | TCP | 23 | 远程登录明文协议，现代安全场景少用 |
| HTTP | TCP | 80 | Web 请求 / 响应基础 |
| SMTP | TCP | 25 | 邮件发送 |
| POP3 | TCP | 110 | 邮件接收 |

端口号是面试速记点，但不要把“常见端口”误认为所有环境都固定不变。实际工程里端口可以配置，安全版本协议也可能使用其他端口。
