# 基础语法

> C++ 与 C# 对照入门 —— 从熟悉的 C# 语法迁移到 C++

---

## 学习目标

已有 C# 基础的前提下，快速补齐 C++ 独有的语法概念。重点关注**与 C# 不同之处**——相同的部分（循环、条件判断、函数定义）一掠而过。

---

## 核心差异速览

| 概念 | C# | C++ |
|------|-----|-----|
| 类型系统 | 类型最终可转换为 `object`（值类型需要装箱） | 没有统一根类型，值语义是默认选择 |
| 空引用 | `null` | `nullptr`（C++11 起） |
| 字符串 | `string`（不可变，引用类型） | `std::string`（可变，值语义） |
| 数组 | `int[]`（引用类型，有长度） | `int arr[5]`（栈上定长）/ `std::vector<int>` |
| 参数传递 | 默认按值（引用类型传引用副本） | 按值 / 按指针 / 按引用（三种明确选择） |
| 内存管理 | 托管堆由 GC 回收，非托管资源仍需释放 | 优先自动存储期与 RAII，必要时使用智能指针 |
| 命名空间 | `namespace X { }` | `namespace X { }`（语法相同） |
| 编译 | 通常编译为 IL，再由 JIT/AOT 执行 | 通常先生成目标文件，再链接为本机程序或库 |

## 学习路线

### 1. 指针与引用

C++ 与 C# 最核心的差异之一，是对象的存储位置、生命周期与所有权可以显式选择。注意：C# 的引用类型通常位于托管堆，但 JIT 仍可能做逃逸分析等优化；不要把“类必定在堆上”当成语言保证。

```
T        直接持有对象        ← 值语义，存储位置由上下文决定
T*       指针（可为空、可改指向）
T&       引用（不能为空的别名，初始化后不能改绑）
```

- 指针运算只应在同一数组（含尾后位置）范围内使用，越界运算属于未定义行为
- 空指针：`nullptr`
- `const T*` vs `T* const`（const 位置决定谁不可变）
- 优先用引用表达“必定存在的借用”，用指针表达“可能为空或需要改指向”

### 2. const 体系

C++ 的 const 比 C# 的 readonly/const 强大得多：

- `const int x = 5` — 常量值
- `const T* p` — 指向的内容不可改
- `T* const p` — 指针本身不可改
- `void Foo() const` — 成员函数不修改成员变量

### 3. 编译与链接

C# 项目一键编译；C++ 区分**编译**（.cpp → .obj）和**链接**（.obj → .exe），头文件（.h）负责声明，源文件（.cpp）负责定义。

- `#include` 不是 C# 的 `using`：它在预处理阶段包含文件内容，而 `using` 主要影响名称查找
- 头文件保护：`#pragma once`
- 前向声明：减少编译依赖
- 声明告诉编译器“名字和类型是什么”，定义真正创建实体；重复定义通常会触发 ODR/链接问题

### 4. 输入输出

```cpp
#include <iostream>
std::cout << "Hello " << name << std::endl;
std::cin >> age;
```

### 5. 类型转换

C++ 有四种显式转换，比 C# 的 `(T)x` 更明确：

| 转换 | 用途 |
|------|------|
| `static_cast<T>` | 相关类型转换（最常用） |
| `dynamic_cast<T>` | 运行时多态转换（需要虚函数） |
| `const_cast<T>` | 去掉 const（少用） |
| `reinterpret_cast<T>` | 重新解释内存（极危险，少用） |
