## 2. 核心原则：性价比排序

以下权重是面向“国内游戏客户端实习面试”的通用学习建议，不代表每家公司固定打分。

| 考察项 | 建议权重 | 为什么重要 | 你当前的策略 |
|---|---:|---|---|
| 项目深度与表达 | 30%-35% | 实习面试最容易拉开差距；能证明你真的做过系统、踩过坑、能交付 | Backpack Survivor 是王牌，要讲设计取舍、Bug 排查、性能判断和 Build 验收，而不是只列功能 |
| C++ / 算法 | 30%-35% | 笔试、一面基础和大厂筛选强相关；C++ 是游戏客户端常见门槛 | 每天都碰：算法保持手感，C++ 用 C# 对比法补内存、生命周期、STL 和对象模型 |
| Unity / C# 工程能力 | 20%-25% | 直接决定你能否胜任客户端功能开发；也是你已有优势 | 用项目继续证明组件化、事件、ScriptableObject、对象池、UGUI、Profiler 和发布流程 |
| 计网 / OS / 图形学基础 | 10%-15% | 中大厂会问底层理解，图形学会加分，但通常不是实习首要筛选项 | 先保证计网 / OS 高频题能解释，再用 GAMES101 / Unity 小实验启动图形学 |
| Lua / 热更新 | 5%-10% | 国内游戏客户端常见技术栈，但实习阶段多为“了解流程和边界” | 先了解 Lua 语法、C# 互调、xLua / tolua 思路和资源热更流程，不包装成掌握 |

### 时间分配优先级

1. 【通用学习建议】C++ 和算法每天都要碰，不能只靠周末突击。
2. 【项目事实 + 通用建议】项目是你的强项，但要从“做了什么”升级到“为什么这样设计、怎么验证、踩坑后怎么改”。
3. 【通用学习建议】Unity / C# 工程能力继续围绕项目补证据：Profiler、Build、Bug 复盘、模块边界、数据驱动。
4. 【通用学习建议】计网 / OS 先学面试高频和能关联项目的问题，例如线程、内存、TCP/UDP、可靠传输、资源加载。
5. 【通用学习建议】图形学和 Lua / 热更新是加分项，优先级低于算法和 C++，但要在大厂暑期实习前至少能讲清基本概念。

### C++ 对比 C# 学习法

| C# 已有理解 | C++ 对应要补 | 面试表达目标 |
|---|---|---|
| class 是引用类型，由 GC 管理 | 栈对象、堆对象、裸指针、智能指针、析构、RAII | 能说清“谁拥有资源，什么时候释放” |
| `List<T>` / `Dictionary<K,V>` | `vector` / `unordered_map` / `map` / 迭代器失效 | 能解释容器选择和常见复杂度 |
| 事件 / 委托 | 函数指针、lambda、`std::function` 的基本概念 | 能类比但不混淆托管委托和 C++ 可调用对象 |
| Unity 生命周期 | C++ 对象生命周期、构造 / 析构、拷贝 / 移动 | 能解释对象何时创建、复制、销毁 |

## 6. 阶段四：秋招（2027.09-2027.11）

## 8. 三个贯穿全程的原则

### 原则一：算法和 C++ 每天都要碰

- 【通用学习建议】算法和 C++ 都是“手感型能力”，断 2 周就会明显退步。
- 【通用学习建议】每天至少保证：1 道算法题或 1 道错题复盘，外加 30 分钟 C++ 阅读 / 编码 / 总结。
- 【通用学习建议】题解不要只写答案，要写：题型、关键不变量、复杂度、边界、C# 与 C++ 差异。

### 原则二：项目是王牌，面试主动讲设计取舍

- 【项目事实】Backpack Survivor 已经具备 15 分钟单局闭环、纯 C# 网格背包、邻接构筑、对象池、波次导演、掉落经济、Build 验收和 Bug 复盘。
- 【通用学习建议】面试中不要等面试官“发现”项目深度，要主动把项目讲成设计题：为什么背包做纯 C#，为什么 UI 只投影，为什么 RuleBook / Resolver 分层，为什么对象池重点是状态复位，为什么某些优化暂缓。
- 【通用学习建议】每个技术亮点都准备“背景 -> 方案 -> Bug / 取舍 -> 验证 -> 后续改进”五段式。

### 原则三：图形学是锦上添花，优先级低于算法和 C++

- 【通用学习建议】图形学对游戏客户端是加分项，但在实习筛选中通常不如算法、C++ 和项目经历刚性。
- 【通用学习建议】大三上不要为图形学牺牲算法和 C++；大三下再启动渲染管线、坐标变换、光照和 Shader 基础。
- 【通用学习建议】图形学学习必须配 Unity 小实验，避免只背概念。

## 9. 一句话总结

用 Backpack Survivor 证明你能独立做出可交付 Unity 项目，同时用每天不断线的算法和 C++ 补齐大厂筛选硬门槛，再用计网、OS、图形学和 Lua / 热更新把面试上限逐步抬高。

## 10. 使用说明

这份总纲不是一次性读完就结束的文章，而是后续“按周生成学习内容”的总地图。

### 每周使用方式

每周开始时，带着本总纲向导师提供以下信息：

| 信息 | 示例 |
|---|---|
| 当前阶段 | 阶段一：大三上，2026.10 第 2 周 |
| 本周可用时间 | 30h；其中周六可集中 6h |
| 上周完成 | LeetCode 7 题，C++ 学完引用和 `vector`，项目讲稿写了对象池部分 |
| 当前卡点 | DP 题不会建状态；C++ 指针和引用容易混；项目性能表达不够顺 |
| 求职节点 | 本周准备投长沙 5 家 Unity 实习 |
| 希望输出 | 生成本周每日计划、题单、C++ 学习任务、项目表达练习和周末复盘模板 |

### 导师每周应输出什么

- 本周目标：不要超过 3 个主目标。
- 每日任务：算法、C++、项目 / 基础按天拆开。
- 验收方式：每项任务都要有可检查产出，例如题解、笔记、代码、讲稿、投递记录。
- 风险提醒：如果某项内容会挤压 P0 任务，要明确降级或移到下周。
- 周末复盘：记录完成情况、失败原因、下周调整和新增面试问题。

### 每月复盘方式

每月末对照四个问题检查路线是否跑偏：

1. 算法题量和正确率是否在提高？
2. C++ 是否从“看懂”推进到“能写、能解释、能排错”？
3. Backpack Survivor 是否能讲出更清楚的设计取舍和验证证据？
4. 当前求职阶段的投递动作是否已经提前开始，而不是等窗口结束才准备？

如果四个问题里有两个以上回答“不确定”，下周计划必须收缩范围，先恢复算法、C++ 和投递节奏。
